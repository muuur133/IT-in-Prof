Проверяем нейросеть

Нейросеть пишет черновик. Ответ становится правильным только после твоей проверки. Ниже всё по шагам: что проверять, как и чем доказать.

!
Главное правило

Нейросеть — помощник, не учитель

Она может:

  • пропустить часть задания
  • придумать команду, которой нет
  • перепутать названия
  • написать код, не совпадающий со схемой
  • написать красивый, но неверный текст

После каждого ответа задай себе три вопроса:

  1. Всё ли из задания есть в ответе?
  2. Нет ли противоречий и явных ошибок?
  3. Что я проверил или исправил сам?

Не пиши «всё правильно». Открой задание и сравни ответ с каждым пунктом.

Пример: в задании «создать четыре таблицы». Ты считаешь таблицы в ответе. Если три, ответ неполный.

Техническое задание

ТЗ — описание будущей программы: для кого она, что должна делать и как понять, что она готова. Ты получаешь ТЗ от трёх нейросетей.

Проверь каждое ТЗ по вопросам:

Плохо

«Система должна быть удобной». Так не проверишь.

Хорошо

«Создать задачу можно не больше чем за три действия». Это проверяется.

Возле каждой оценки пиши причину: «Полнота — 4. Есть пользователи, задачи и роли, но нет требований к защите данных». Не просто «5».

База данных, SQL, ER и API

База данных — это хранилище информации. Таблица похожа на таблицу в Excel: столбец — поле, строка — одна запись.

PRIMARY KEY

Уникальный номер записи. У двух пользователей не может быть одинакового id.

FOREIGN KEY

Ссылка на запись в другой таблице.

В задаче есть project_id, по нему видно, к какому проекту она относится.

Один ко многим

Один объект связан со многими.

Один проект — много задач. Одна задача — много комментариев.

ER-диаграмма

Рисунок таблиц и связей между ними. Должна совпадать с SQL-кодом.

Четыре таблица в коде — четыре на схеме.

Проверка SQL-кода

Пример ошибки: в comments есть task_id, но внешнего ключа нет. Ты добавляешь FOREIGN KEY, который связывает comments с tasks, и пишешь об этом в отчёте.

# Заголовок

Знак решётки делает заголовок.

- пункт

Дефис делает пункт списка.

``` код ```

Три обратные кавычки делают блок кода.

Какие файлы нужны

README.md

Главная инструкция: что за проект, зачем он, какие технологии, как установить и запустить, где API.

CHANGELOG.md

История версий: что добавили, изменили, исправили, удалили.

API.md

Методы, адреса, тела запросов и примеры ответов.

Docstring

Текст внутри функции: что делает, что принимает, что возвращает.

Как проверить документ

  1. Открой файл в VS Code.
  2. Включи предпросмотр.
  3. Заголовки, списки и блоки кода должны выглядеть как оформление, а не как значки.
  4. Команды установки и запуска должны работать.
  5. Названия API и полей сверь с лабой 2.
Важно: текст может выглядеть красиво, но с неверной командой запуска он всё равно неверный.

Критерии готовности

Плохо

«Работа сделана хорошо». Так не проверишь.

Хорошо

Как писать отчёт

Формула проверки

Не пиши «я всё проверил, ошибок нет». Пиши, что именно ты сделал.

Действие→ Результат→ Проверка→ Ошибка→ Исправление→ Доказательство
Пример: «Я попросил нейросеть создать восемь эндпоинтов. При проверке увидел, что создание задачи сделано через GET. Заменил на POST. Исправленная таблица — в таблице 2.1».

Если ты не можешь объяснить, что значит код, таблица или термин, эта часть ещё не готова к сдаче.

Проверяй по заданию, а не по впечатлению.
